# BitrixText Forge

[English](../README.md)

Локальное настольное приложение для подготовки сообщений в Bitrix24. Редактируйте исходный текст в Markdown, просматривайте результат и копируйте совместимый BBCode либо обычный текст для ручной вставки в Bitrix24.

Приложение не подключается к Bitrix24, не отправляет сообщения и не хранит учётные данные.

## Руководство пользователя

Пошаговая инструкция по запуску, работе с Markdown, профилями вывода,
специальными вставками, экспортом и настройками находится в
[руководстве пользователя](tutorial/README.md).

## Возможности

- Редактор Markdown с автоматической или ручной конвертацией.
- Четыре профиля вывода: **Bitrix24 Full Message**, **Bitrix24 Core Safe**, **Plain Text** и **Manual Code Highlight**.
- Предпросмотр AST-документа, итоговый BBCode и диагностика преобразования.
- Поддержка заголовков, списков (включая task list и вложенные), цитат, ссылок, жирного текста, курсива, зачёркивания, кода, изображений и горизонтальных линий.
- Поддержка Markdown-таблиц с сохранением форматирования ячеек и текстовым fallback: документированного BBCode-тега таблицы в Bitrix24 нет.
- Специальные вставки: `[u]`, `[user=ID]`, `[color=#HEX]`, `[size=N]` и `[icon=URL ...]` с проверкой параметров.
- Открытие и сохранение Markdown, экспорт результата в текст или JSON, отдельный экспорт изображений и таблиц в выбранный каталог, копирование обычного или форматированного результата в системный буфер обмена.
- Встроенные и пользовательские шаблоны, автосохранение, восстановление сессии и список недавних файлов.
- Все настройки, черновики и шаблоны хранятся локально.

## Требования

- Rust stable с поддержкой edition 2024.
- Windows является основной платформой. Linux и macOS поддерживаются при наличии окружения, совместимого с `eframe`.

## Сборка

Для Linux-целей требуются Docker Desktop с включённым Buildx и доступом к
контейнерам Linux. Скрипт по умолчанию собирает оптимизированные нативные
бинарники для Linux `x86_64`, Linux `aarch64` и Windows `x86_64`, экспортируя
их в каталог `dist`:

```powershell
.\scripts\build-docker.ps1 -Clean
```

Имена каталогов и файлов используют канонические названия архитектур:

- `dist\linux-x86_64\bitrixtext_forge-linux-x86_64`;
- `dist\linux-aarch64\bitrixtext_forge-linux-aarch64`;
- `dist\windows-x86_64\bitrixtext_forge-windows-x86_64.exe`.

Чтобы собрать только одну Linux-архитектуру или изменить каталог артефактов:

```powershell
.\scripts\build-docker.ps1 -Platform linux/x86_64 -OutputDirectory artifacts -Clean
```

Прежние Docker-алиасы `linux/amd64` и `linux/arm64` также принимаются.
Для сборки только Linux используйте `-SkipWindows`. Windows-артефакт
собирается нативно командой `cargo build --release`, поэтому скрипт для него
нужно запускать на Windows. Для macOS требуется нативный Mac: Docker на
Linux/Windows не включает распространяемый SDK Apple, необходимый для
корректной сборки приложения.

Для публикации GitHub Release сначала обновите версию пакета в `Cargo.toml`,
затем отправьте совпадающий тег. Например, после установки версии `0.1.2`:

```powershell
git tag v0.1.2
git push origin v0.1.2
```

Workflow соберёт Linux `x86_64`, Linux `aarch64` и Windows `x86_64` и приложит
к GitHub Release Linux-архивы `.tar.gz` и Windows-файл `.exe`.

## Вход и результат

Приложение открывает файлы `.md`, `.markdown` и `.txt`. Исходник сохраняется как UTF-8 Markdown; результат можно экспортировать в `.txt`, `.bbcode.txt` или JSON с полями `markdown`, `bbcode` и `profile`. Кнопка **📦 Ресурсы** отдельно спрашивает каталог для изображений и таблиц.

Full Message генерирует расширенное подмножество BBCode Bitrix24, включая `[b]`, `[i]`, `[u]`, `[s]`, `[url]`, `[color]`, `[size]`, `[icon]` и `[user]`. Core Safe оставляет только базовое форматирование. Plain Text не генерирует BBCode.

В профиле Full Message блоки кода оборачиваются в `[code]`; Core Safe по
умолчанию использует читаемый отступ в четыре пробела, а Manual Code Highlight
выводит код без `[code]`. Изображения представлены читаемыми ссылками, а не
`[img]`; локальные файлы можно скопировать через **📦 Ресурсы**, а внешние
адреса сохраняются как `.url`-ссылки без загрузки из сети. HTML не исполняется,
а неподдерживаемые или потенциально теряющие форматирование конструкции
отмечаются в диагностике.
