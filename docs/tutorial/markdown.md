# Markdown и специальные вставки

Редактор принимает Markdown в кодировке UTF-8. Пустая строка обычно отделяет
один блок документа от другого. Конвертер сохраняет текстовое содержимое и
преобразует поддерживаемые конструкции в зависимости от выбранного профиля.

## Поддерживаемые конструкции

| Markdown | Пример | Назначение |
| --- | --- | --- |
| Заголовки | `# Заголовок`, `## Подзаголовок` | Заголовки H1–H6. |
| Жирный текст | `**важно**` | Жирное начертание. |
| Курсив | `*заметка*` | Курсивное начертание. |
| Зачёркивание | `~~устарело~~` | Зачёркнутый текст. |
| Ссылка | `[текст](https://example.com)` | Ссылка с подписью. |
| Ненумерованный список | `- пункт` | Маркированный список. |
| Нумерованный список | `1. пункт` | Нумерованный список. |
| Вложенный список | Отступ перед `- пункт` | Список с уровнями вложенности. |
| Task list | `- [ ] задача`, `- [x] готово` | Чекбоксы задач. |
| Цитата | `> текст` | Цитата. |
| Кодовый блок | ```` ```rust ```` | Многострочный код с необязательным языком. |
| Изображение | `![описание](https://example.com/a.png)` | Изображение с альтернативным текстом. |
| Таблица | Синтаксис таблиц GitHub-Flavored Markdown | Таблица с заголовком и выравниванием. |
| Горизонтальная линия | `---` | Разделитель. |

Для строки с переносом можно использовать обычный перевод строки или HTML
`<br>`. Поддерживается ограниченный набор inline-HTML:
`<b>`, `<strong>`, `<i>`, `<em>`, `<u>`, `<s>`, `<del>`, `<strike>`,
`<a href="...">` и `<br>`. HTML не исполняется как код. Неподдерживаемый HTML
сохраняется как текст и отмечается в **Диагностике**.

## Примеры

### Списки, ссылки и цитаты

```markdown
## План релиза

1. Подготовить сборку
2. Проверить:
   - ссылки;
   - форматирование;
   - вложенные списки.

> Важное замечание для команды.
```

### Код

````markdown
```rust
fn main() {
    println!("Привет, Bitrix24!");
}
```
````

Язык после открывающих трёх обратных кавычек используется при ручной
подсветке. Реальное поведение блока зависит от профиля: в полном профиле
используется `[code]`, в безопасном профиле по умолчанию — отступ в четыре
пробела, а `Manual Code Highlight` оформляет код вручную. Подробности
приведены в [описании профилей](profiles-and-export.md#профили-вывода).

### Изображение

```markdown
![Скриншот отчёта](https://example.com/report.png "large")
```

Изображения не встраиваются в сообщение и не превращаются в `[img]`. В
результате остаётся читаемая ссылка с альтернативным текстом. Поэтому перед
публикацией убедитесь, что адрес изображения доступен получателям.

### Таблица

```markdown
| Сотрудник | Статус | Часы |
| :--- | :---: | ---: |
| Иван | Готово | 8 |
| Ольга | В работе | 6 |
```

Таблица подготавливается к отдельному `.xlsx`-файлу. Чтобы выбрать место и
создать файл, нажмите **📦 Ресурсы** и укажите каталог. В сообщении остаётся
имя файла таблицы. Это ограничение связано с тем, что документированный тег
таблицы в BBCode Bitrix24 отсутствует.

### Экспорт изображений и таблиц

Кнопка **📦 Ресурсы** в верхней панели явно показывает, куда будут записаны
ресурсы текущего Markdown-документа:

- `table_1.xlsx`, `table_2.xlsx` и т. д. — извлечённые таблицы;
- `image_N.<расширение>` — локальные изображения, найденные рядом с исходным
  Markdown-файлом;
- `image_N.url` — Internet Shortcut для внешнего URL, без загрузки из сети;
- `resources.txt` — реестр исходных адресов, альтернативных текстов и
  созданных файлов.

Обычные **💾 Сохранить** и **📤 Экспорт** больше не создают файлы ресурсов
рядом с документом автоматически. Это предотвращает запись в неожиданное
место; каталог всегда выбирается отдельной кнопкой.

## Специальные вставки Bitrix24

У следующих конструкций нет удобного Markdown-аналога:

```text
[u]Подчёркнутый текст[/u]
[user=123]Иван Иванов[/user]
[color=#ff0000]Красный текст[/color]
[size=18]Крупный текст[/size]
[icon=https://example.com/icon.png size=16 title=Иконка]
```

Надёжнее всего вставлять их через вкладку **Спецвставки**:

1. Поставьте курсор в редакторе или выделите текст, который нужно заменить.
2. Откройте **➕ Спецвставки** или вкладку **Спецвставки** справа.
3. Выберите нужный мастер.
4. Заполните поля и нажмите **Вставить**.
5. Если текст был выделен, вставка заменит выделение; если курсор не удалось
   определить, фрагмент будет добавлен в конец документа.

### Проверка параметров

- **[u] Подчёркивание**: текст необязателен; по умолчанию используется
  `текст`.
- **[user] Упоминание**: ID сотрудника обязателен; отображаемое имя можно
  оставить пустым.
- **[size] Размер шрифта**: допустим диапазон от 8 до 30 px; доступны
  пресеты.
- **[color] Цвет текста**: нужен HEX-цвет из 3 или 6 символов, например
  `#f00` или `#ff0000`; доступны палитра и пресеты.
- **[icon] Иконка**: URL обязателен; параметры `size` и `title` необязательны.

Конвертер проверяет эти параметры. Некорректный HEX, размер вне диапазона,
пустой ID или пустой URL и соответствующее предупреждение появляются во
вкладке **Диагностика**.

## Что не следует вводить вручную

Markdown-конвертер сам генерирует обычные теги результата (`[b]`, `[i]`,
`[s]`, `[url]` и другие). Не нужно заменять Markdown на произвольный BBCode
в исходнике. Из ручных Bitrix24-вставок распознаются только `[u]`, `[user]`,
`[color]`, `[size]` и `[icon]`, перечисленные выше.

Теги `[send]`, `[call]`, `[put]`, `[context]` и `[chat]` исключены из области
поддержки. Они остаются обычным текстом и помечаются предупреждением.
Произвольные неподдерживаемые теги также не превращаются в исполняемую
разметку.

## Рекомендации для устойчивого результата

1. Используйте абсолютные URL для ссылок и изображений, если сообщение будет
   открываться на другом компьютере.
2. Для кода закрывайте блок тем же количеством обратных кавычек, которым он
   был открыт.
3. После вставки текста из внешнего редактора просмотрите **Диагностику**:
   табы и необычные HTML-конструкции могут изменить разбор Markdown.
4. Проверяйте результат в выбранном профиле: один и тот же исходник
   намеренно выглядит по-разному в `Full Message`, `Core Safe` и `Plain Text`.
